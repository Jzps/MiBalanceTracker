## Requisitos Funcionales

| ID        | Requisito funcional                             | Descripción                                                                                                                        | Interacción del usuario / Resultado esperado                                                                                                      |
| :-------- | :---------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------ |
| **RF-01** | Registro de usuario                             | El sistema debe permitir al usuario crear una cuenta mediante nombre, correo electrónico, contraseña y confirmación de contraseña. | El usuario diligencia el formulario y, si los datos son válidos, el sistema crea su cuenta.                                                       |
| **RF-02** | Inicio de sesión                                | El sistema debe permitir al usuario acceder mediante sus credenciales registradas.                                                 | El usuario ingresa correo y contraseña. Si son correctos, accede al sistema.                                                                      |
| **RF-03** | Configuración inicial del ingreso               | El sistema debe solicitar obligatoriamente el salario o ingreso fijo mensual durante el primer acceso.                             | El usuario registra su salario fijo. El sistema almacena este valor y lo utiliza como referencia para los cálculos financieros iniciales.         |
| **RF-04** | Dashboard financiero                            | El sistema debe mostrar un resumen de la situación financiera actual del usuario.                                                  | El usuario visualiza ingresos, gastos, disponible, presupuestos, metas y otros indicadores obtenidos de la información registrada.                |
| **RF-05** | Registrar movimientos                           | El sistema debe permitir registrar ingresos y gastos.                                                                              | El usuario selecciona el tipo de movimiento, categoría, descripción, monto, fecha, método de pago y notas opcionales.                             |
| **RF-06** | Consultar movimientos                           | El sistema debe mostrar los movimientos financieros registrados por el usuario.                                                    | El usuario puede consultar el historial de ingresos y gastos y revisar su información.                                                            |
| **RF-07** | Editar movimientos                              | El sistema debe permitir modificar información de movimientos existentes.                                                          | El usuario corrige un movimiento y el sistema actualiza automáticamente los cálculos relacionados.                                                |
| **RF-08** | Eliminar movimientos                            | El sistema debe permitir eliminar movimientos registrados.                                                                         | El usuario elimina un movimiento y el sistema recalcula la información financiera afectada.                                                       |
| **RF-09** | Gestionar categorías                            | El sistema debe permitir clasificar los ingresos y gastos mediante categorías financieras.                                         | El usuario selecciona una categoría al registrar un movimiento y puede utilizar las categorías disponibles para organizar su información.         |
| **RF-10** | Crear presupuestos                              | El sistema debe permitir establecer límites de gasto para determinadas categorías y períodos.                                      | El usuario selecciona una categoría, define un límite y establece el período correspondiente.                                                     |
| **RF-11** | Consultar progreso de presupuestos              | El sistema debe calcular cuánto se ha gastado, cuánto queda disponible y qué porcentaje del presupuesto se ha utilizado.           | El usuario consulta un presupuesto y visualiza su progreso actualizado según los movimientos registrados.                                         |
| **RF-12** | Generar alertas de presupuesto                  | El sistema debe mostrar alertas estáticas cuando un presupuesto alcance determinados porcentajes o sea superado.                   | Al alcanzar un límite definido, el sistema muestra mensajes como “Has utilizado el 80% de tu presupuesto” o “Has superado el presupuesto”.        |
| **RF-13** | Crear metas de ahorro                           | El sistema debe permitir crear metas financieras con un nombre, monto objetivo y fecha objetivo.                                   | El usuario crea una meta, por ejemplo, para comprar un computador, y el sistema registra el objetivo.                                             |
| **RF-14** | Gestionar fondo de emergencia                   | El sistema debe permitir crear y administrar un fondo de emergencia dentro del módulo de Metas y Fondo de emergencia.              | El usuario establece un objetivo para su fondo y consulta el dinero acumulado y el progreso.                                                      |
| **RF-15** | Registrar aportes a metas y fondo de emergencia | El sistema debe permitir registrar dinero destinado a una meta o fondo de emergencia sin tratarlo como un gasto ordinario.         | El usuario agrega un aporte y el sistema actualiza el monto ahorrado, porcentaje de progreso y valor pendiente.                                   |
| **RF-16** | Consultar progreso de ahorro                    | El sistema debe calcular el avance de cada meta o fondo de emergencia.                                                             | El usuario visualiza monto objetivo, monto acumulado, porcentaje alcanzado y monto restante.                                                      |
| **RF-17** | Gestionar deudas                                | El sistema debe permitir registrar y consultar obligaciones financieras pendientes.                                                | El usuario registra una deuda con información como monto inicial, saldo pendiente, fecha de pago y pago mínimo.                                   |
| **RF-18** | Registrar pagos de deuda                        | El sistema debe permitir registrar pagos realizados sobre una deuda.                                                               | El usuario registra un pago y el sistema actualiza el saldo pendiente y el porcentaje pagado.                                                     |
| **RF-19** | Análisis financiero                             | El sistema debe presentar información estadística basada en los datos registrados por el usuario.                                  | El usuario consulta gastos por categoría, ingresos, gastos, ahorro y evolución de la información financiera.                                      |
| **RF-20** | Comparación entre períodos                      | El sistema debe permitir comparar información financiera de diferentes períodos registrados.                                       | El usuario puede observar cambios entre meses en ingresos, gastos, ahorro y cumplimiento de presupuestos.                                         |
| **RF-21** | Visualización gráfica                           | El sistema debe representar determinados datos financieros mediante gráficos o indicadores visuales.                               | El usuario puede comprender más fácilmente la distribución y evolución de sus finanzas.                                                           |
| **RF-22** | Educación financiera                            | El sistema debe proporcionar contenidos básicos relacionados con la administración del dinero.                                     | El usuario consulta conceptos como presupuesto, ahorro, necesidades, deseos, deudas y fondo de emergencia.                                        |
| **RF-23** | Consulta de 50/30/20                            | El sistema debe ofrecer una herramienta informativa y de cálculo basada en la regla 50/30/20.                                      | El usuario consulta la distribución orientativa de sus ingresos y puede comparar la referencia con sus datos reales.                              |
| **RF-24** | Personalización de distribución                 | El sistema debe permitir modificar los porcentajes de distribución utilizados como referencia en 50/30/20, siempre que sumen 100%. | El usuario puede establecer una distribución diferente y el sistema recalcula los valores de referencia sin modificar los movimientos históricos. |
| **RF-25** | Configuración de cuenta                         | El sistema debe permitir al usuario administrar información y preferencias básicas de su cuenta.                                   | El usuario consulta o modifica la información disponible en Configuración.                                                                        |
| **RF-26** | Actualización automática de información         | El sistema debe actualizar los datos relacionados cuando se registre, modifique o elimine información financiera.                  | Un cambio en Movimientos debe reflejarse en Dashboard, Presupuestos, Análisis y demás módulos que dependan de ese dato.                           |
| **RF-27** | Gestión de períodos mensuales                   | El sistema debe conservar el historial de períodos anteriores y permitir trabajar con el período actual.                           | Los movimientos y resultados de meses anteriores permanecen registrados mientras se genera información correspondiente al nuevo período.          |

## Requisitos No Funcionales

| ID         | Requisito no funcional      | Descripción                                                                                                                         | Criterio esperado                                                                                                         |
| :--------- | :-------------------------- | :---------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------ |
| **RNF-01** | Usabilidad                  | La interfaz debe ser sencilla e intuitiva para que el usuario pueda comprender y utilizar las funciones sin conocimientos técnicos. | El usuario debe poder navegar entre los módulos mediante el menú lateral y reconocer fácilmente las acciones principales. |
| **RNF-02** | Diseño responsive           | La interfaz debe adaptarse a diferentes tamaños de pantalla.                                                                        | Las principales funciones deben poder visualizarse correctamente en computadores, tabletas y dispositivos móviles.        |
| **RNF-03** | Rendimiento                 | El sistema debe responder de manera adecuada ante las operaciones realizadas por el usuario.                                        | Los registros, consultas y cálculos habituales deben ejecutarse sin demoras innecesarias.                                 |
| **RNF-04** | Seguridad de autenticación  | El sistema debe proteger el acceso a las cuentas mediante autenticación.                                                            | Un usuario no autenticado no debe poder acceder a la información financiera de otro usuario.                              |
| **RNF-05** | Privacidad de información   | La información financiera debe mantenerse asociada exclusivamente a la cuenta correspondiente.                                      | Cada usuario solamente podrá consultar y modificar sus propios datos.                                                     |
| **RNF-06** | Integridad de datos         | El sistema debe mantener la coherencia entre la información almacenada y los cálculos realizados.                                   | Los totales, presupuestos, metas y análisis deben actualizarse correctamente después de modificar información.            |
| **RNF-07** | Consistencia                | La información mostrada en los diferentes módulos debe corresponder con los datos almacenados.                                      | Un mismo movimiento debe producir los mismos resultados en Dashboard, Presupuestos y Análisis cuando corresponda.         |
| **RNF-08** | Mantenibilidad              | El código debe organizarse de manera que facilite futuras modificaciones y ampliaciones.                                            | La aplicación debe separar adecuadamente la presentación, lógica del sistema y acceso a datos.                            |
| **RNF-09** | Compatibilidad              | La aplicación debe funcionar en navegadores web actuales.                                                                           | Las funciones principales deben operar correctamente en navegadores modernos.                                             |
| **RNF-10** | Escalabilidad básica        | La estructura del sistema debe permitir incorporar mejoras futuras sin reconstruir completamente la aplicación.                     | El diseño debe permitir agregar posteriormente funcionalidades avanzadas sin afectar las funciones principales.           |
| **RNF-11** | Tecnologías definidas       | El sistema debe desarrollarse utilizando las tecnologías establecidas para el proyecto.                                             | Se utilizarán HTML, CSS, PHP, MySQL y XAMPP como tecnologías principales del desarrollo.                                  |
| **RNF-12** | Facilidad de comprensión    | Los mensajes, formularios e indicadores deben utilizar lenguaje claro y comprensible.                                               | Las alertas y resultados deben explicar al usuario qué está ocurriendo con su información financiera.                     |
| **RNF-13** | Disponibilidad local        | Durante el desarrollo y pruebas, el sistema debe poder ejecutarse en un entorno local.                                              | La aplicación debe funcionar utilizando XAMPP, Apache y MySQL.                                                            |
| **RNF-14** | Recuperación y consistencia | Las operaciones de modificación de información deben evitar estados inconsistentes en la base de datos.                             | Los datos relacionados deben actualizarse correctamente cuando una operación sea completada.                              |

## Reglas de Negocio

| ID        | Regla de negocio                        | Regla                                                                                                                                                                      | Aplicación dentro del sistema                                                                                                 |
| :-------- | :-------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------------- |
| **RN-01** | Un usuario, sus datos                   | Cada usuario solamente puede acceder a la información financiera asociada a su propia cuenta.                                                                              | Los movimientos, presupuestos, metas, deudas y configuraciones estarán relacionados con el usuario correspondiente.           |
| **RN-02** | Ingreso inicial obligatorio             | Para comenzar a utilizar las funciones financieras principales, el usuario debe registrar su salario o ingreso fijo mensual.                                               | El sistema não debe permitir finalizar la configuración inicial sin registrar este dato.                                      |
| **RN-03** | Salario como referencia inicial         | El ingreso registrado durante la configuración inicial representa el salario o ingreso fijo principal del usuario.                                                         | Este valor servirá como referencia para el Dashboard y la distribución 50/30/20.                                              |
| **RN-04** | Otros ingresos                          | Los ingresos adicionales podrán registrarse posteriormente mediante Movimientos.                                                                                           | El usuario podrá registrar otros ingresos sin modificar necesariamente el salario fijo configurado inicialmente.              |
| **RN-05** | Movimientos                             | Los movimientos representan dinero que efectivamente ingresó o salió de la disponibilidad del usuario.                                                                     | Los movimientos deben clasificarse como ingreso o gasto y quedar registrados con fecha y categoría.                           |
| **RN-06** | Ahorro independiente del gasto          | El ahorro destinado a metas o al fondo de emergencia no se considera un gasto ordinario.                                                                                   | Los aportes se gestionan desde Metas y Fondo de emergencia y actualizan el progreso de ahorro.                                |
| **RN-07** | Metas y fondo de emergencia             | Las metas financieras y el fondo de emergencia pertenecen al mismo módulo de ahorro.                                                                                       | El usuario administra ambos desde la sección “Metas y Fondo de emergencia”.                                                   |
| **RN-08** | Meta con propósito                      | Una meta de ahorro debe tener un objetivo definido.                                                                                                                        | La meta debe establecer al menos un nombre y un monto objetivo.                                                               |
| **RN-09** | Presupuesto como límite                 | Un presupuesto representa un límite planificado de gasto para una categoría y período determinados.                                                                        | El sistema compara los gastos registrados con el límite establecido.                                                          |
| **RN-10** | Cálculo del presupuesto                 | El valor gastado de un presupuesto corresponde a la suma de los movimientos de gasto asociados a su categoría y período.                                                   | Cada nuevo gasto correspondiente actualiza el progreso del presupuesto.                                                       |
| **RN-11** | Alerta preventiva                       | Cuando un presupuesto alcance el porcentaje de alerta establecido, el sistema debe mostrar una advertencia preventiva.                                                     | Por ejemplo: al alcanzar el 80%, se muestra una alerta amarilla.                                                              |
| **RN-12** | Alerta de excedente                     | Cuando el gasto supere el límite de un presupuesto, el sistema debe informar que el presupuesto fue excedido.                                                              | Por ejemplo: “Has superado el presupuesto de alimentación”.                                                                   |
| **RN-13** | Alertas determinísticas                 | Las alertas iniciales deben generarse mediante reglas y cálculos previamente definidos, no mediante detección de hábitos o inteligencia artificial.                        | El mensaje depende de valores concretos como porcentaje utilizado, límite superado o progreso.                                |
| **RN-14** | 50/30/20 como referencia                | La regla 50/30/20 es una herramienta orientativa y no una obligación para el usuario.                                                                                      | El sistema presenta la distribución como referencia para organizar los ingresos.                                              |
| **RN-15** | Distribución válida                     | La suma de los porcentajes personalizados de 50/30/20 debe ser exactamente 100%.                                                                                           | El sistema debe impedir guardar una distribución cuya suma sea diferente de 100%.                                             |
| **RN-16** | Historial inalterable por planificación | Modificar la distribución 50/30/20 no debe modificar los movimientos financieros históricos.                                                                               | Solamente cambian los valores de referencia y cálculos asociados al plan.                                                     |
| **RN-17** | Cálculo disponible                      | El dinero disponible debe calcularse a partir de los ingresos y salidas que correspondan al período.                                                                       | El Dashboard debe actualizar el disponible cuando cambien los datos financieros.                                              |
| **RN-18** | Deuda pendiente                         | El saldo pendiente de una deuda corresponde al monto inicial menos los pagos registrados.                                                                                  | Cada pago reduce el saldo pendiente de la deuda.                                                                              |
| **RN-19** | Pago de deuda                           | Un pago realizado sobre una deuda debe quedar registrado y reflejarse en la información financiera correspondiente.                                                        | El sistema actualiza el saldo de la deuda y los indicadores financieros relacionados.                                         |
| **RN-20** | Integración entre módulos               | Los datos registrados deben alimentar automáticamente los módulos que dependan de ellos.                                                                                   | Un gasto puede afectar Dashboard, Presupuestos, Análisis y alertas sin que el usuario tenga que registrarlo nuevamente.       |
| **RN-21** | Edición de información                  | Cuando un movimiento sea modificado, todos los cálculos dependientes deben actualizarse utilizando el nuevo valor.                                                         | Si un gasto cambia de $100.000 a $80.000, el presupuesto y los totales deben recalcularse.                                    |
| **RN-22** | Eliminación de información              | Cuando se elimine un movimiento, los cálculos relacionados deben actualizarse sin ese movimiento.                                                                          | El gasto eliminado deja de formar parte de los totales y presupuestos correspondientes.                                       |
| **RN-23** | Historial mensual                       | Los datos de períodos anteriores deben conservarse para permitir consultas y comparaciones.                                                                                | Al comenzar un nuevo mes, la información del mes anterior no debe desaparecer.                                                |
| **RN-24** | Categorías                              | Todo gasto o ingreso registrado debe estar asociado a una categoría válida.                                                                                                | Las categorías permiten organizar los movimientos y realizar análisis posteriores.                                            |
| **RN-25** | Sin modificación histórica              | Las nuevas configuraciones o presupuestos no deben alterar los movimientos que ya fueron registrados.                                                                      | La planificación afecta la interpretación de los datos, no los hechos financieros históricos.                                 |
| **RN-26** | Alcance de primera versión              | La primera versión no debe depender de inteligencia artificial, reconocimiento de patrones, aprendizaje de hábitos ni gamificación para cumplir sus funciones principales. | Estas características pueden considerarse mejoras futuras, pero no son necesarias para el funcionamiento del sistema inicial. |
